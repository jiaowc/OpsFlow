# OpsFlow 社区版与企业版的边界

OpsFlow 采用 Open Core 模式：

- **社区版**（本仓库，MIT）：完整可用的构建、发布、回滚平台，永久免费，不含任何 License 校验代码。
- **企业版**（商业订阅，单独的私有仓库）：在社区版核心之上，通过扩展点加入下表中的商业功能，并按 License 开通。

两个版本使用同一套库结构和迁移脚本，可以在同一个库上直接切换镜像：社区版 → 企业版 → 社区版，数据都保留。
了解企业版：<https://www.opslink.cn>

## 1. 功能对照

| 能力 | 社区版 | 企业版 |
|---|---|---|
| 项目、服务、环境、集群、构建节点 | ✅ | ✅ |
| 凭据与集成：钥匙串、组件接入（Git、Harbor、K8s 等） | ✅ | ✅ |
| 流水线 Job：创建、构建、部署、日志、阶段视图 | ✅ | ✅ |
| 生产与非生产环境的部署和回滚（按权限码控制） | ✅ | ✅ |
| Git Webhook 自动构建 | ✅ | ✅ |
| 流水线模板、步骤定义 | ✅ | ✅ |
| 本地账号、LDAP 登录、角色权限（RBAC） | ✅ | ✅ |
| 两步验证（动态码 + 恢复码，可设为全员强制） | ✅ | ✅ |
| 工作台统计、站内信 | ✅ | ✅ |
| 上线任务与审批流程（开通后生产发布可强制走上线任务） | — | ✅ |
| 操作审计查询 | — | ✅ |
| 外部通知（飞书审批通知、流水线结果群通知） | — | ✅ |
| 单点登录（飞书、企业微信、钉钉） | — | ✅ |
| 企业品牌（登录页、控制台 Logo 和名称） | — | ✅ |

说明：

- 社区版也会记录操作审计日志，升级到企业版后可以查询到升级前的历史。
- 企业版 License 到期后有 7 天宽限期，之后商业功能关闭、回到社区版能力，数据和流水线任务都保留；续费只需导入新的 License。

## 2. 明确不收费的能力

为了保证社区版本身可用，以下能力不会移到企业版：

- 单机、私有化部署与基础配置；
- 端到端：拉代码 → 构建镜像 → 推送仓库 → 部署（含生产环境）→ 回滚；
- Git Webhook 自动构建的基础能力；
- 流水线模板和步骤定义的编辑；
- 本地账号和 LDAP 登录。

## 3. 扩展点

企业版不修改社区版代码，只通过 `opsflow-core` 里 `com.opsflow.spi` 包的扩展点接入，例如：

| 扩展点 | 用途 |
|---|---|
| `UiExtension` | 追加菜单、页面片段、脚本、样式和多语言文案（含登录页） |
| `WebSecurityExtension` | 追加免登录路径、免 CSRF 校验的回调路径 |
| `UserAccountExtension` | 用户来源和账号附加字段 |
| `SystemConfigExtension` | 配置类型校验、保存后处理、通知选项 |
| `StatisticsContributor` | 工作台统计 |
| `BuildJobLifecycleListener` | 流水线任务生命周期回调 |
| `ResourceReferenceChecker` | 删除资源前的引用检查 |

社区版里这些扩展点都没有实现，行为与默认值一致。核心模块有守护测试（`CoreDoesNotDependOnCommercialCodeTest`），保证核心代码不依赖任何商业代码。

## 4. 数据库

商业功能用到的表（如 `deploy_task`、`approval_flow`、`approval_record`、`user_feishu`）也由社区版的 Flyway 迁移建立，社区版里这些表保持为空或不被读写。这样两个版本可以共用一个库，切换时无需迁移数据。
